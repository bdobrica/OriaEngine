# Live-test deployment preparation — 2026-10-29

## Deployment

The dedicated `oria-live-test` Compose project uses the full-stack entry point.
Oria application and MCP images were built locally from commit `85cba8c`, without
publishing them. SecondContext uses the published gateway image pinned to
`sha256:1986ee30c532940775a065c2c2836f9150e9013798409582cdc06cdfa977c04d`.
The image contains its migration executable and SQL assets.

Both migration jobs completed successfully. PostgreSQL, Redis, Qdrant,
SecondContext, MCP, gateway and worker reached healthy status. Only gateway port
8001 is published, on host loopback. Configuration and secrets remain in the
ignored deployment environment file with mode `0600`; no credential values or
operator payloads are included here. Server-Tools was not modified.

## Checks performed

- Quiet Compose validation passed with the real configured environment.
- Private MCP transport checks passed for exact-time natal charts, transits and
  unknown-time availability behavior.
- Live SecondContext checks passed for authenticated fixed-phrase memory
  ingestion, embeddings, provider responses, scope/session validation, explicit
  prior-topic memory retrieval, subject purge and repeated purge. These used
  disposable synthetic subjects, which were purged after each check.
- Gateway liveness and dependency readiness returned 200. Missing/incorrect
  webhook secrets returned 403; authenticated malformed JSON returned 400 and an
  authenticated oversized body returned 413. No Telegram event was admitted by
  these rejection checks.
- The configured Telegram token was accepted by `getMe`. Before setup, webhook
  registration was empty and the pending-update count was zero. No message was
  sent to a Telegram user by these checks.
- Public HTTPS at `o.ublo.ro` had a trusted hostname-valid certificate expiring
  2027-01-27. Before proxy replacement, the root returned 200 with an empty body.
- A webhook-only Nginx candidate retained the operator's certificate paths and
  TLS settings, disabled request logging, preserved the received secret header,
  and returned 404 outside the webhook route. It passed `nginx -t` in an isolated
  container using a disposable certificate, separately from host validation.
- The operator installed the candidate and reported successful host validation
  and reload. Public HTTPS checks subsequently returned 404 for `/`, `/healthz`
  and `/readyz`; missing/incorrect webhook secrets returned 403, the correct
  forwarded secret with malformed JSON returned 400, and an oversized request
  returned 413. No event was admitted by these checks.
- Explicit webhook registration completed successfully, preserving pending
  updates. Telegram subsequently confirmed the expected URL and exactly
  `message`/`callback_query` update types, with zero pending updates and no
  reported delivery error. Registration is not itself evidence of a delivered
  Telegram reply.
- During initial preparation, all 14 release-selection tests passed. The full
  `make verify` gate was not run on this server.

## Observed continuity limitation

A same-session follow-up failed to recall a topic supplied only in the preceding
message. Explicitly ingested prior-topic memory was retrieved successfully in a
separate check. Inspection of the available SecondContext source indicates that
response context retrieves explicit memories but does not replay session
transcripts. No component was changed to work around this result. It does not
establish general conversational continuity or complete that release-gate item.
