# OriaEngine operational telemetry v1

This private operator interface adds JSON log fields and a local CLI snapshot.
Telegram, Astrology MCP and SecondContext wire formats remain unchanged. Consumers
should ignore unknown additive fields. No public metrics HTTP endpoint is added.

## JSON log samples

Existing timestamp, level, event, correlation ID, update ID and status/latency fields
retain their meanings. Optional `job_id` is the canonical internal event/deletion
UUID; retries retain it and create a new correlation ID. IDs are diagnostic context,
never metric labels. There is no user/chat/session ID or raw payload dimension.
Ingress `event="job_admitted"` links normalized-update correlation to that canonical
job UUID, including duplicate receipt admission. Only typed UUID extras are accepted.

`event="metric"` carries `metric_name`, `outcome`, `value=1`, optional nonnegative
finite `duration_ms` and `error_category`. Counter records omit duration; timed
records increment an attempt count and provide one latency observation.

Supported names:

- `database_transaction`, `queue_admission`, `queue_publish`, `worker_dispatch`,
  `worker_process`, `worker_retry`, `worker_dead`;
- `mcp_natal`, `mcp_transits`, `second_context_respond`, `second_context_remember`,
  `second_context_purge`, `telegram_send`, `telegram_update`;
- `update_deduplicated`, `inbound_limited`, `consent_disclosure`,
  `policy_input_block`, `policy_output_block`, `policy_high_stakes`;
- `deletion_process`, `deletion_retry`.

Outcomes are `success`, `error`, `cancelled`. Error categories are `database`,
`redis`, `mcp`, `second_context`, `telegram`, `timeout`, `limited`, `internal`.
They derive from exception types, never messages. Boundary validation/protocol/timeouts
translated to MCP/SecondContext unavailable exceptions retain that component category.
Cancellation propagates and is not a dependency error.

`event="configuration_summary"` carries only `app_env` (`development`, `test`,
`production`), `role` (`gateway`, `polling`, `worker`) and booleans
`webhook_enabled`, `llm_enabled`, `context_auth_enabled`. URLs, passwords, tokens,
keys, policy strings and arbitrary settings are omitted.

## CLI snapshot

`python -m oria_engine.operations` / `make metrics` emits one JSON object on stdout:

```json
{"version":1,"checks":{"database":true,"redis":true},"gauges":{"queue_depth":0}}
```

The example abbreviates gauges. The full fixed key set is:

- `queue_pending`, `queue_processing`, `queue_ready`, `queue_sent`, `queue_dead`,
  `queue_depth`, `queue_oldest_age_seconds`;
- `users`, `consent_accepted`, `consent_declined`, `consent_revoked`;
- `onboarding_drafts`, `onboarding_confirmed`, `onboarding_chart_cached`;
- `deletion_confirmation`, `deletion_requested`, `deletion_local_deleted`,
  `deletion_context_deleted`, `deletion_redis_deleted`, `deletion_completed`,
  `deletion_retrying`, `deletion_oldest_age_seconds`.

Values are nonnegative numbers, or all `null` when the database snapshot fails.
Queue depth includes pending/processing/ready retries and expired work awaiting cleanup.
Ages measure oldest nonterminal event creation or unfinished confirmed deletion request;
empty sets yield zero. Terminal totals include retained unlinked receipts. Deletion
retrying counts unfinished jobs with a failure code; pending notices remain completed.

Consent gauges count latest revision per retained user across policy versions.
Onboarding gauges count retained draft, confirmed-profile and derived-cache rows;
cache presence does not assert current consent or calculation-version validity.
These are current-state gauges, not lifetime counters or cohort conversion rates.
Deletion lowers user/consent/profile counts; completed deletion markers remain.

PostgreSQL is queried in a read-only repeatable-read transaction, with a three-second
per-statement timeout and ten-second overall deadline. Redis PING runs independently
with a three-second deadline. Redis failure preserves PostgreSQL gauges. Exit status
is zero when both checks succeed, one otherwise. Invalid config or unexpected CLI
failure emits a fixed stderr diagnostic and exits one. Cancellation propagates.
Routine operational logs go to stderr.

Telemetry is best effort and non-authoritative. Dropped logs, crashes, retries,
rollbacks and log level affect log-derived counts. Consumers MUST group only by
fixed metric names/outcomes/categories, not request/job/update IDs. Operators MUST
keep snapshots and logs private; they are not user-facing APIs.
